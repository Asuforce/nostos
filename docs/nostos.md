# プロジェクト概要: Nostos (ノストス)

## 1. 背景と目的

家族のSlackにて `#todo` チャンネルを作成し、メッセージとしてTodoを書き込み、完了したタスクには `:done:` スタンプ（リアクション）を付ける運用を行っている。
しかし、Todoが増えると未完了タスクが上に流れて埋もれてしまう課題がある。
本プロジェクト「Nostos」は、埋もれた未完了タスクを毎朝自動で収集し、リマインドとして再通知することで、この課題を解決する。

また、本プロジェクトは最初から **OSS (Open Source Software)** として Public リポジトリで開発・公開し、同じ悩みを持つ他のユーザーやコミュニティにも還元できる汎用的なツールを目指す。

## 2. システム構成（技術スタック）

* **言語**: Rust (WebAssemblyにコンパイル)
* **インフラ**: Cloudflare Workers
* **トリガー**: Cloudflare Workers Cron Triggers (`0 0 * * *` ※UTC 0:00 = JST 9:00)
* **デプロイ**: GitHub Actions (`wrangler` を使用した自動デプロイ)
* **外部API**: Slack API (`conversations.history`, `chat.postMessage`)
* **ライセンス**: MIT License (または Apache 2.0)

## 3. 機能要件 (Phase 1)

### 対象と取得範囲

* **対象チャンネル**: `#todo` チャンネル
* **対象メッセージ**: 親メッセージのみ（スレッド内のメッセージは対象外）
* **対象期間**: 過去90日以内のメッセージ（Slack無料版の制限に準拠）

### 未完了タスクの判定条件

以下の**すべて**を満たすものを「未完了タスク」として抽出する。

1. Slackの `reactions` 配列に `:done:` （または指定のスタンプ）が含まれていないこと。
2. ユーザーの発言であること。（`bot_id` や `subtype` が含まれるメッセージは除外する。※リマインダー自身の発言を再度Todoとして拾ってしまう無限ループを防ぐため必須）

### アクション

* 毎朝AM 9:00 (JST) に起動。
* 未完了タスクを抽出し、該当ポストへのリンクを作る。
* 未完了タスクが1件以上存在する場合のみ、Slackの `#todo` チャンネルに親メッセージを投稿し、そのスレッドに該当ポストへのリンクを貼る。

## 4. 処理フロー

1. **Cron起動**: Cloudflare Workerがスケジュールにより起動。
2. **環境変数ロード**: CloudflareのSecrets / GitHub Secretsから設定を読み込む。
3. **メッセージ取得**: Slack API `conversations.history` をコールして直近のメッセージを取得。
4. **フィルタリング**: 取得したメッセージ群に対し、「未完了タスクの判定条件」を適用する。
5. **メッセージ構築**: 件数を知らせる親メッセージと、各ポストへのリンクを並べたスレッド返信を作成する。リンクは `auth.test` のワークスペース URL とチャンネル ID、`ts` から組み立てる。
6. **通知**: Slack API `chat.postMessage` で親メッセージを投稿し、返った `ts` を `thread_ts` にしてリンクをスレッドに投稿する。

## 5. 今後の拡張構想 (Phase 2: 記録用)

* Todoメッセージの末尾に日付や時刻（例: `10/31` や `@14:00`）を記載した場合、それをパースして優先順位（ソート順）を上げる機能。
* 完了用スタンプ名（現在は `:done:` 固定）を環境変数から任意に変更可能にするカスタマイズ機能。

## 6. OSS公開に向けた開発ガイドライン

Publicリポジトリとして安全かつ高品質に公開するため、以下の設計ルールを遵守する。

1. **機密情報の完全分離（セキュリティ）**:
   * APIトークン、チャンネルID、テナント情報などは絶対にコードやリポジトリ内にコミットしない。
   * `.gitignore` に `.dev.vars` や `wrangler.toml` 内の秘密情報を除外する設定を入れる。
   * `wrangler.toml.example` を用意し、設定項目のテンプレートを公開する。

2. **汎用性と設定性**:
   * 他のユーザーが自分のSlackワークスペースでフォーク（またはセルフホスト）して使えるよう、環境変数で動作をカスタマイズ可能にする。

3. **ドキュメンテーション**:
   * 誰でもセットアップできるよう、環境構築手順、Slack Appのパーミッション設定（OAuth Scopes）、Cloudflareのデプロイ手順をわかりやすくまとめた `README.md` を作成する。
   * `LICENSE` (MIT) および `CONTRIBUTING.md` を配置する。

* **TODOコメントの活用:** コードの中にあえて一部「ユーザー自身が実装する課題（`// TODO:`）」を残し、私にロジックを書かせるプロセスを挟んでください。
* **OSS視点の助言:** セキュリティチェック（誤ってトークンをコミットしないか等）や、他の開発者が見て読みやすいイディオマティックなRustコード（Rust API Guidelinesに沿った命名等）のアドバイスも積極的に行なってください。
